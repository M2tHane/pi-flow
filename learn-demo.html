1. 安装（只做一次）

git clone <pi-flow 仓库地址> ~/tools/pi-flow
cd ~/tools/pi-flow
npm install --omit=dev        # 必须：Pi 不会替本地包装依赖
pi install ~/tools/pi-flow    # 全局登记
pi list                       # 确认有 pi-flow
在 pi 里用 /login 或 ~/.pi/agent/models.json 配好模型，然后 /flow-config 给各角色选模型（全局，只需一次；例如把 designer 换成前端审美好的模型）。插件（Serena、codegraph、联网搜索）按需装，/flow doctor 会告诉你缺什么。

2. 在项目里开始

cd ~/code/my-app     # git 仓库；新项目先 git init
pi
/flow-build "做一个……"            # 新项目：需求 → 原型 → 规划 → 实施
/flow-build --feature "……"        # 已有项目加功能
/flow-fix "……"                    # 修 bug
已有项目开工前，先确认 workflow.yaml 的 commands（模板写的是 pnpm）；规划阶段 architect 也会按技术栈起草命令，你批准规划时一并应用。

5. 出问题时

  • /flow-status 顶部的"需要你处理"永远是第一站；--detail 看任务明细与验收结果。
  • /flow run <run_id> 看某次子进程调用了哪些工具、最后说了什么。
  • /flow doctor 检查状态完整性、依赖、残留 worktree。
  • 在 pi-flow 仓库执行 node scripts/flow-view.ts <项目目录>，生成真实项目的交互视图（时间线、DAG、成本、事件）。
  • 关掉 pi 不会丢进度：重新打开执行 /flow-resume，模块的工作区与本地提交都还在。
