# 撰写 PRD

1. 先读用户的描述（任务说明与 handoff），列出缺失的关键信息：目标用户、核心场景、范围边界、约束。
2. 关键信息缺失且无法合理假设时，调用 flow_block，**一次只问一个问题**，并给出你建议的默认答案。用户用 /flow unblock 回答后你会被重新派发，回答在 handoff 中。
3. 可以合理假设的，直接写入"约束与假设"并标明是假设。
4. 按 docs/PRD.md 的模板填写，每节简洁：
   - 功能范围：按功能列出输入、输出、主要流程。
   - 非目标：至少三条，明确不做什么。
   - 验收标准：每条都可被自动化测试验证，写清输入与期望输出（例如"POST /orders 缺少 items 时返回 422 与字段错误"）。
5. 未决问题留在"未决问题"一节，交给用户在闸门审批时决定。
6. 完成后 flow_note 写明做了哪些假设，再 flow_submit。
