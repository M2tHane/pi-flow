# 做原型

原型的目的是让用户在写代码前点一遍、提出修改，不是交付产品。所以要像真的一样可点，但不接后端。

## 文件
- `prototype/styles.css`：先定下共用的视觉语言（CSS 变量：颜色、字号、间距、圆角、阴影；基础组件：按钮、输入框、表单、卡片、表格、分页、
  弹窗、提示）。所有页面都只 `<link>` 这一份。
- `prototype/<页面>.html`：每个 MVP 页面一个，写本页的标记与少量原生 JavaScript。
- `prototype/index.html`：导航页，列出所有页面与一句话说明。

## 每个页面
- 用贴近真实的示例数据（合理的名字、日期、数值、状态），列表给几行，默认展示有数据的样子。
- 每个功能都能点：新增 → 弹窗或表单 → 提交后列表出现新项；编辑 → 标明哪些字段可改；删除 → 确认后移除；筛选与搜索 → 真的过滤；
  点一行 → 看详情。
- 四种状态：加载、空、错误、无权限，用页面角落的切换器演示。不会出现的状态标 N/A 与理由。
- 内容溢出：单项内容过高用固定高度加滚动；列表很长用分页（可点击换页、切换每页条数）；其他溢出加滚动条。

## 风格
照需求说明定下的风格做，排版、间距、配色要统一并符合项目调性；避免千篇一律的渐变和大圆角卡片堆砌。
