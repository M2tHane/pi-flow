# 做原型

原型的目的是让用户在写代码前点一遍、提出修改，不是交付产品。所以要像真的一样可点，但不接后端。

## 文件
- `docs/design/theme.css`：先定下共用的视觉语言（CSS 变量：颜色、字号、间距、圆角、阴影；基础组件：按钮、输入框、表单、卡片、表格、分页、
  弹窗、提示）。不绑定框架，所有原型页面都 `<link href="../docs/design/theme.css">`。只给原型演示用的样式（状态切换器等）放 `prototype/prototype.css`。
- `DESIGN.md`（仓库根目录）：设计规范，见下一节。
- `prototype/<页面>.html`：每个 MVP 页面一个，写本页的标记与少量原生 JavaScript。
- `prototype/index.html`：导航页，列出所有页面与一句话说明。

## DESIGN.md
用户批准原型时一起批准它；之后实现界面、加新功能都照它做，所以写成别人照着就能做出一致界面的说明：
1. **风格**：一两句话说清调性与理由（来自需求说明）。
2. **设计变量**：颜色（主色、语义色、文字、背景、边框）、字体与字号层级、间距、圆角、阴影，每个写 theme.css 里的变量名与用途。
3. **组件**：按钮、输入框、表单、卡片、表格、分页、弹窗、提示等，每个写有哪些变体、什么时候用哪个、对应的类名。
4. **布局**：页面骨架（导航、页头、内容区）、栅格与断点。
5. **四种状态**：加载、空、错误、无权限各自怎么呈现（用哪个组件、文案的口吻）。
6. **该做与不该做**：几条容易做偏的地方。

已有 DESIGN.md 时（加新功能）：沿用，只扩展；新增的变量与组件补进去，不改已有的。

## 每个页面
- 用贴近真实的示例数据（合理的名字、日期、数值、状态），列表给几行，默认展示有数据的样子。
- 每个功能都能点：新增 → 弹窗或表单 → 提交后列表出现新项；编辑 → 标明哪些字段可改；删除 → 确认后移除；筛选与搜索 → 真的过滤；
  点一行 → 看详情。
- 四种状态：加载、空、错误、无权限，用页面角落的切换器演示。不会出现的状态标 N/A 与理由。
- 内容溢出：单项内容过高用固定高度加滚动；列表很长用分页（可点击换页、切换每页条数）；其他溢出加滚动条。

## 风格
照需求说明定下的风格做，排版、间距、配色要统一并符合项目调性；避免千篇一律的渐变和大圆角卡片堆砌。
