# 后端规则

## 分层
1. 分层与依赖方向：接口层（handler / route）→ 服务层（service）→ 数据访问层（repository）；下层不得 import 上层。
2. 接口层只做参数解析、调用服务、映射响应；业务逻辑一律放在服务层。
3. 输入校验在接口层入口完成（使用契约或 shared 中的 schema）；服务层假定输入已校验。
4. 数据库访问只经数据访问层；服务层中不得出现 SQL 字符串。拼接查询一律用参数绑定，不拼接字符串。
5. 列表与关联查询避免 N+1：一次查询取回需要的关联数据。

## 错误处理
6. 错误类型以契约与 ARCHITECTURE.md 为准；同一项目内统一，不抛裸字符串。
7. 业务异常（资源不存在、无权限、校验失败）向上抛出，由接口层映射为响应；未预期的异常记录上下文后继续抛出。
8. 对外错误响应只包含错误码与可读信息，不包含堆栈与内部细节。
9. 资源不存在与无权访问对外统一表现为"不存在"（不暴露资源是否存在）；有权查看但无权操作才返回"禁止"。

## 接口
10. 新增公共接口必须先在契约中存在；契约外的接口不得暴露。
11. HTTP 接口路径用小写连字符、资源名用复数（/order-items/{id}），嵌套不超过两层；响应格式与契约一致。
12. 模块按目录组织（如 src/server/<模块>/），不修改集中路由表或集中导出文件。

## 日志
13. 关键操作与错误记录日志，带上下文（模块、关键 id）；不得记录密钥、令牌与完整请求体。
